# lane4dev • apps 视觉与交互重构规格

**Design & UI Refactor Spec · 2026-11-25**  
适用站点为 apps.tangyu.me，覆盖英文和简体中文。设计、开发与内容审校共用同一份验收标准。

## Problem Statement · 问题

访客来到展厅要回答三个问题：这款产品帮我完成什么、在哪里获取、它怎样处理我的数据。现在，首页先展示模拟终端、在线信号和固定的「01 Platform」，实际产品却覆盖 Android 和 Chrome。首页和顶栏把第二、第三款产品排在不同位置。进入产品页后，轮播的自动运动和重复的能力计数占用注意力。进入政策页后，读者还要逐段滚动才能找到数据去向。

主站用简短署名、常规字重与大块留白呈现作者，展厅应让访客认出同一位作者，并把主要版面交给产品界面。顶栏尺寸与主题行为以实际发布的主站为基线。英文眉标采用本次指定的编辑格式，主站公开首页可见的同源元素包括 HARDWARE、SOFTWARE 等英文分组。[主站](https://tangyu.me/) · [主站样式表](https://tangyu.me/assets/css/main.css) · [展厅](https://apps.tangyu.me/)

## Solution · 方案

首页让访客从真实界面挑选产品。概览页用一次可读的前后对照说明产品价值，只突出一个可用下载渠道。政策和支持页把关键事实放到标题下，用目录直达原文。展厅采用黑白灰 CTA，层次由底色、1px 描边、字重和间距建立。Linear 的界面层次与 Raycast 的产品操作展示仅作为这两项设计的参考。[Linear](https://linear.app/) · [Raycast](https://www.raycast.com/)

## User Stories · 用户故事

1. 作为主站读者，我希望从字标、留白和署名认出作者，以便放心进入展厅。
2. 作为首次访客，我希望一眼看见产品用途与真实界面，以便决定先了解哪一款。
3. 作为回访者，我希望各处产品顺序一致，以便凭位置找到产品。
4. 作为双语读者，我希望在当前产品或文档切换语言，以便接着阅读同一主题。
5. 作为手机访客，我希望一只手即可操作菜单和产品导航，以便随时查找支持。
6. 作为下载者，我希望一眼辨认正式分发渠道，以便下载适合的平台版本。
7. 作为侧载用户，我希望在 APK 链接旁读到适用限制，以便决定安装哪个版本。
8. 作为扩展用户，我希望读清截图中的原文和摘要，以便判断它与我的阅读习惯是否相符。
9. 作为写作者，我希望给同一段原文切换语境，以便看懂 Beyond Words 怎样改变表达。
10. 作为记账用户，我希望看见交易如何进入分类报表，以便理解记账后的结果。
11. 作为语境包使用者，我希望从产品导航直达指南，以便复制导入地址或下载示例。
12. 作为隐私敏感用户，我希望分清设备存储与发往服务商的内容，以便决定是否使用产品。
13. 作为政策读者，我希望打开某一条款的链接即可看见标题，以便引用或核实它。
14. 作为求助者，我希望能从支持页找到与当前产品有关的操作和邮箱，以便说明问题。
15. 作为键盘或屏幕阅读器用户，我希望辨认焦点、当前页和所选语境，以便独立走完流程。
16. 作为对运动敏感的读者，我希望自己控制截图与示例，以便按自己的节奏阅读。
17. 作为维护者，我希望产品次序、可用下载和译文各有明确来源，以便一次发布在所有入口得到一致呈现。

**语言与当前位置。** 顶栏仅一个「EN / 中文」控件，当前语言显示为文本并加下划线，另一语言为有明确可访问名称的链接。使用已配置的翻译配对，保持页面类型、产品、canonical、hreflang 与 x-default。章锚有明确译文映射时保留，否则落在译文标题。菜单内和页脚移除重复切换。当前产品在一级导航可辨；二级导航只给精确匹配的项标记当前页，进入政策页不高亮 Overview。

### 2. Design Tokens

以语义 CSS 自定义属性提供以下值。浅深切换只替换颜色映射，间距和字号跨主题共用。颜色策略取自主站白底、灰黑字和微冷深灰顶栏，截屏保留产品原色。页面外壳、导航、文字、卡片、控件均用中性色，满足至少 90% 中性基调；产品原图不计入外壳配色。

| --- | --- | --- | --- |
| `--bg` | `#FFFFFF` | `#252627` | 页面 |
| `--surface` | `#F7F7F7` | `#2D2E2F` | 图框、对照片、摘要 |
| `--surface-raised` | `#F0F0F0` | `#38393A` | 选中分段、按压底 |
| `--header-bg` | `#FFFFFF` | `#313233` | 固定顶栏，不透明 |
| `--ink` | `#191919` | `#F8F8F8` | 标题、导航 |
| `--body` | `#454545` | `#DEDEDE` | 正文 |
| `--muted` | `#606060` | `#B8BABC` | 眉标、图注、字标后缀 |
| `--line` | `rgb(0 0 0 / 13%)` | `rgb(255 255 255 / 16%)` | 装饰性分隔与图片描边 |
| `--line-hover` | `rgb(0 0 0 / 27%)` | `rgb(255 255 255 / 32%)` | 卡片悬停 |
| `--control-line` | `#737373` | `#A3A3A3` | 依靠轮廓识别的控件 |

| `--focus` | `#292929` | `#F5F5F5` | 2px 外焦点环，与控件间留 3px |

按实际色值计算，muted 文字在 surface-raised 上的对比度为浅色 5.52:1、深色 5.95:1；control-line 在同一底色上分别为 4.16:1、4.59:1。细分隔线仅用于分组，输入、焦点与选中状态使用各自的高对比 token。

主题沿用主站已发布的 auto 策略：按访客本地时间在晨晚切换，沿用主站 07:00 / 19:00 转换逻辑，提供一次手动切换，在当前站点会话与同一时段内记住选择。首次绘制即应用主题；存储不可用时保持可读，无脚本时采用系统配色。两个域名分别保存选择，无需跨域写入。[主站](https://tangyu.me/)

### 3. 布局、断点与组件行为

| 条件（CSS 视口宽度） | 全局与首页 | 产品与阅读页 |
| --- | --- | --- |
| 窄屏 < 768px | 正文边距 20px。Hero 单列，项目卡按眉标、标题、用途、截图、入口排列；原则卡单列。页脚两列，低于 480px 上下排列。 | 前后对照纵排；摘要两列，低于 480px 单列。目录在正文上方折叠。产品栏容不下时产品名占第一行，链接占第二行。 |
| 中屏 768–1023px | 正文边距 32px，卡片文字和图各占一半；原则卡三列。 | 对照横排，摘要两列，目录仍可展开。 |
| 宽屏 ≥ 1024px | 正文边距至少 48px，上限 1200px 并居中；项目卡文图 7:5。 | 目录 200px、间隔 48px、正文目标 68ch（65–72ch）；摘要三或四等列。 |
| 顶栏独立断点 | 跟随主站，左右留白在 ≤1024px 时为 20px，其余为 60px。≤1080px 或文本放大后放不下时收起产品列表，字标、语言入口和菜单仍在同一栏。 | 主题入口在空间不足时移入展开菜单。产品栏、标题与正文共享内容边线。 |

**全局顶栏。** 使用正常展示状态下的主站几何。字标「lane4dev • apps」15.75px / 400，英文字距 −1px，品牌图形 24px；后缀用 muted。一级链接 18px / 400，桌面沿用 64px 项间距。菜单从顶栏向下展开，按钮报告展开状态，Escape 关闭并归还焦点，关闭后的链接退出 Tab 顺序。关闭脚本时，菜单仍可用原生展开控件或可见链接访问。产品及文档页两级导航随滚动保持可见；矮屏若双栏占可视高度超过三分之一，优先保留产品栏，让全局栏随页面滚出，锚点偏移同步更新。提供跳至正文入口。[主站顶栏样式](https://tangyu.me/assets/css/main.css)

**首页。** Hero 用一条眉标、一个 H1、一句用途说明和一个跳至现有项目区的 CTA。删除模拟终端、LIVE/ACTIVE、光斑和整行统计。首张卡对应 Beyond Words，眉标为「01 · ANDROID · GOOGLE PLAY」，其后依次为「02 · CHROME · CHROME WEB STORE」「03 · ANDROID · APK」。每卡一个概览链接，标题可作链接，箭头随该链接响应。右侧裁出真实操作区域：Beyond Words 的输入与改写结果、AI Heading Brief 的原标题与摘要、Accounted For 的分类报表。手机保留 UI 关键字段，允许换裁切点；图框预留宽高比并使用 1px 边线。下方三张原则卡各用一条标题和一句说明。页脚前只留一句署名式收尾，建议「这些工具，来自我每天遇到的小问题。」英文对应「These tools grew out of problems I run into every day.」

**通用交互状态。** 静止卡片用 line，精确指针悬停只增强描边并上移 2px；触屏和减少动态效果模式保持原位。主按钮依序使用 action、action-hover、action-active。正文链接常显下划线，悬停加深，键盘焦点使用外焦点环；主题按钮、菜单和下载均有文字或可访问名称。选中标签以字重与底线共同表示，禁用的轨道边界按钮使用原生禁用状态。控件实际点按区至少 44×44px，正文行内链接按自然行高。加载、复制成功或失败只就地反馈。页面不使用滚动劫持、3D 透视、渐变标题或 SaaS 式填充口号。

**产品页顺序。** 产品栏 → Hero（平台、产品名、用途、获取方式）→ 界面截图与图注 → 能力对照 → 必要的使用步骤 → Transparency → 页脚。去掉重复的平台、能力数量、流程步数统计。截图建立认知，能力示例解释截图中看不出的输入与结果。

| 产品 | Hero 唯一主操作 | 次要入口与能力演示 |
| --- | --- | --- |
| Beyond Words | Google Play | 有发布地址时才显示 Download APK 文字链接，旁注「APK 版的部分功能不可用」。示例固定原文「把周报发我，今天下班前要。」选择「同事沟通」后显示「请在今天下班前把周报发给我，谢谢。」选择「英文翻译」后显示「Please send me the weekly report by the end of today.」两版保留期限和任务。 |
| AI Heading Brief | Chrome Web Store | 无 APK。静态示例左侧列一个标题及两句原文，右侧给该节的一句摘要；保留原文与摘要的层级。现有一张宽屏截图，整幅呈现，可另取局部作首页预览。 |
| Accounted For | Download APK（取当前发布记录的地址） | 当前商店关闭、测试邀请地址为空，省略相应入口。示例左侧列「午餐 ¥32、晚餐 ¥48」，右侧列「餐饮 ¥80 · 2 笔」；使用示例账目。将来有正式商店时，商店成为主操作，APK 转为文字链接。 |

有效商店优先，其次选已有正式 APK。仅有有效测试邀请时使用明确标为「加入测试」的入口。所有地址缺失时展示分发说明和 Support 文本链接。中英文共用渠道配置，静态演示分别编写两种语言的例文。

**截图轨道。** Beyond Words 和 Accounted For 各有六张竖图。采用原生横向滚动、CSS Scroll Snap 按起点吸附；首屏和中段让下一张露出 24–40px。手机显示一张主体，较宽时可并列多张；桌面内容不足一轨时全部静态显示。产品页完整保留截图比例，首页可裁切。每张配本地化图注和说明操作结果的替代文本；英文页使用现有中文界面时在图注说明语言。支持触摸、触控板，以及具名的前后按钮；键盘每次前进一项，抵达首尾时相应按钮禁用。无自动播放、复制幻灯片或循环跳转。单图只呈现图与图注。资源不可读时保留图注和描述。

**能力对照。** 共用一个带 Before / After 标题的示例区域，桌面左右等宽，手机依次为语境、原文、结果。Beyond Words 采用两个经审校的预设语境；标签支持左右键、Home/End，所选标签关联对应面板并保留焦点。切换只更新示例，页面高度预留较长译文空间。其他产品直接显示一组静态对照。关闭脚本后所有示例按文档顺序可读；演示采用固定内容，无需输入、密钥或在线模型。

### 4. 文档与法务

标题上方标明产品名，H1 直接使用文档名称。标题下保留已有生效或更新日期，紧接 At a glance 摘要，再进入目录与正文。每页提供 3–4 项摘要，每项用短标签、一句事实与对应正文锚点。摘要由产品和文档类型共同决定。Privacy 说明数据流向，Terms 摘要概括适用服务、用户责任或收费，Support 摘要提供实际支持路径。缺乏已核实依据的条目应换为有原文依据的另一项。不得把待确认日期渲染成已生效日期。

| 产品 | Privacy 摘要的内容依据 | Terms / Support 应突出的话题 |
| --- | --- | --- |
| Beyond Words | 无需手动注册，云功能使用匿名标识；历史保存在设备；内置转换经后端转交 Gemini；自定义模型密钥保存在设备安全存储，并用于向所选服务认证。 | 生成结果复核、Google Play 订阅与恢复、应用内举报及邮件支持。 |
| AI Heading Brief | 所选章节发送至配置的提供商或端点；API Key 使用浏览器扩展同步存储，开启同步时可能跨设备；摘要保留在打开页面。 | 第三方模型服务与费用、端点配置、网页兼容性及故障反馈。该产品不能标注「API Key 仅在本地安全存储」。 |
| Accounted For | 无需注册登录；账本在设备保存；导出文件经系统分享；备份不含附件原文件。 | 账务记录用途、备份恢复、单独保存附件及支持邮箱。 |

**阅读布局。** 桌面目录固定在产品栏下 16px，可在剩余视口内独立滚动。目录从实际 H2 生成；较长指南可加一级 H3。每项有稳定、唯一的片段地址，沿用已有对外锚点，并以底线或侧线提示当前章节。直接打开片段、前进后退、点击目录时标题完整可见；自然滚动只更新当前位置，不堆积历史记录。中窄屏用标题为「本页目录」的原生可展开控件，选中后收起并定位标题。正文行高 1.75；H2 前后分别留 48px、16px。长 URL 可换行，代码和宽表仅在各自容器内横向滚动。

**Custom Packs 指南。** 使用同一阅读模板，在摘要中给出指南实际涵盖的格式、下载与导入方式。保留现有 JSON 下载、导入地址、复制反馈、代码块和表格。复制失败时显示可选取的原始 URL。法务摘要须由产品维护者逐项对照当前生产行为和对应正文，尤其区分「不要求登录」「使用匿名标识」和「无追踪」所指的不同事实。[Beyond Words 隐私政策](https://apps.tangyu.me/beyond-words/privacy/) · [AI Heading Brief 隐私政策](https://apps.tangyu.me/heading-brief/privacy/) · [Accounted For 隐私政策](https://apps.tangyu.me/accounted-for/privacy/)

## Testing Decisions · 验收标准

**验收入口已确认：从构建后的完整页面走用户路径。** 沿用站点校验与干净的 Jekyll 构建，前者只检查源文件和占位符。下面各项在浏览器中验证链接目的地、可见内容、操作与焦点，不依赖 CSS 类名或组件内部状态。

| 编号 | 操作 | 通过条件 |
| --- | --- | --- |
| AC01 路由与语言 | 遍历两种语言的首页、3 个概览、9 个 Privacy / Terms / Support 页及 1 个指南，每种语言 14 页 | 全部 28 页可直达；切换语言后仍是同产品同文档，来回可用。每页仅一个语言入口，导航、标题和辅助名称使用相应语言。 |
| AC02 品牌与层次 | 在 390px 与 1440px 并排对照主站正常顶栏，分别查看浅深主题 | 顶栏高度、左右边距、字标字号和字重与基线一致（像素取整容差 1px）。后缀可读，主站链接可达；两栏相接无缝。主题切换后，同站内导航保留选择。 |
| AC03 首页与页脚 | 从首页通过卡片进产品，再从页脚换产品、访问主站、GitHub 或邮箱 | 顶栏、移动菜单、卡片和页脚同序；三张卡都能凭截图辨别用途。Hero 没有终端或统计栏，原则区只出现一次，页脚前为一句收尾。 |
| AC04 下载与导航 | 三个概览分别检查主操作、次操作和 Transparency；遍历两种语言的产品栏 | 分发渠道与产品表一致，主按钮各一个且目标有效；没有空测试链接。仅 Beyond Words 出现 Custom Packs。Privacy、Terms 从 Transparency 与产品上下文页脚均可达。 |
| AC05 截图与演示 | 分别使用手指、键盘走完六张截图，再查看单图产品；切换两种语境 | 顺序和图注一致，末端停止，等待时不自动位移；单图无空控件。示例保留输入事实，选中态可识别。禁用脚本后仍可阅读截图、图注与示例。 |
| AC06 阅读与准确性 | 三款产品的 Privacy、Terms、Support 对照摘要与正文；从直链和目录跳转后使用浏览器后退 | 每个摘要项都有对应段落且审校通过。标题避开固定栏，桌面正文 65–72ch；手机展开目录可抵达同章。指南的复制、手动取 URL、下载均可用。 |
| AC07 可访问性 | 用 Tab、Shift+Tab、Enter、Escape、方向键完成菜单、下载和示例切换；启用减少动态效果 | 焦点始终可见，菜单关闭后焦点返回，读屏读出当前页与选中态。正常文字对比度 ≥4.5:1，大字和必要控件轮廓 ≥3:1；两主题均通过。减少动态效果后无抬升、自动移动或平滑滚动。 |
| AC08 响应式与回归 | 在 320、390、768、1024、1080、1440px 与桌面 200% 缩放下走查；抽查手机横屏。运行 `python scripts/validate_site.py` 及 `bundle exec jekyll build`，构建目标使用空目录 | 双语页面无整页横向溢出、导航遮挡或截断按钮。保留 canonical、hreflang、APK 发布链接和 JSON 下载地址。源校验和构建均成功，桌面及移动端各留一组关键页面截图。 |

## Out of Scope · 范围边界

交付范围是展厅视觉、导航、内容呈现与验收规格。产品功能、在线改写服务、商店发布、账户系统、政策义务变更、主站全面改版及 canonical 路径迁移另行立项。主站反向入口属于跨仓协作项，展厅团队交付链接文字与目标地址。
