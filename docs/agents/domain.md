# Domain docs

This Jekyll site has one domain glossary. Before exploring a change, read
`CONTEXT.md` at the repository root if present, then read any architecture
decision records (ADRs) in `docs/adr/` that cover the affected area. If either
location is absent, continue with the task. The `domain-modeling` skill creates
these documents when a term or decision is settled.

Use the glossary's terms in issues, proposals, and code. If a term is missing,
check the repository's existing usage and flag genuine gaps for domain modeling.

When a proposal conflicts with a recorded decision, cite the ADR and explain
why the decision merits reconsideration.
